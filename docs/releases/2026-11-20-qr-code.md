# SVG QR code component

Integrated after `4ee0f93`, with a pending minor Changeset for `@plain/ui`.
The manifest remains the local 0.2.0 candidate; this record does not imply npm
publication.

`QRCode`, `QRCodeProps` and `QRCodeErrorCorrectionLevel` are available from
`@plain/ui` and `@plain/ui/qr-code`. The component renders a native SVG from the
local [qrcode encoder](https://github.com/soldair/node-qrcode), pinned in the
lockfile at 1.5.4. It supports exact string values, Unicode, size, L/M/Q/H error
correction, explicit colors, accessible labels/descriptions and native SVG
attributes, events and refs. No remote encoding service is used.

Black ink on white paper remains the default in both themes. The quiet zone is
normalized to at least four modules on every side, following the
[DENSO QR code guidance](https://www.qrcode.com/en/howto/code.html/index.html).
Modules do not animate or mirror in RTL. Six styling slots, two typed color
aliases, unstyled geometry and English/Arabic status messages follow P.UI's
existing customization contract. Empty and unencodable values render text
placeholders without a misleading code. Encoding failures notify the current
callback without repeating when the parent rerenders with a new callback.

The documentation page at `/components/qr-code` includes editable content,
property controls, API notes and an application-owned SVG download. The example
resolves computed fill colors so the exported file works outside its theme scope.

Validation:

- TypeScript, ESLint/workspace boundaries, formatting, library/docs build,
  package verification and the npm pack dry run passed.
- All 258 tests passed: 9 workspace checks, 243 library tests and 6 documentation
  tests. Eleven QR code tests cover native SVG contracts, correction levels,
  Unicode, margins, value updates, empty/error recovery, callback stability,
  colors, slots/tokens, unstyled mode, localization and SSR.
- Seven Chrome 157.0.8103.79 Playwright cases passed. Actual rendered SVG
  screenshots and downloaded SVGs are decoded independently using
  [jsQR](https://github.com/cozmo/jsQR). Cases cover the documentation workflow at
  1440px light/LTR, 320px light/LTR and 390px dark/RTL, all four correction levels,
  Unicode, local color tokens, responsive size, unstyled SVG, and forced colors
  with reduced motion. Empty/oversized content disables the example download and
  recovers when corrected. Scoped Axe WCAG A/AA scans passed. The forced-colors
  scan targets the QR image; its surrounding fixture's native forced-color
  painting was visually inspected, without claiming a whole-page contrast audit.
- Four production-page scenarios passed at 1440px light/LTR, 800px dark/LTR,
  320px light/LTR with motion disabled and 390px dark/RTL. Each verified rendered
  and downloaded codes, editing, empty recovery, no page errors, zero preview and
  document overflow, and no detected scoped Axe violations. The 800px scenario
  also decoded an exported SVG with locally overridden ink. Screenshots were
  inspected.
- The verified archive contains 229 files and is 498,718 bytes. All 105 public
  examples compile, including QRCode. The installed consumer imports the new
  subpath and its types. Every declared export resolves, and QRCode SSR passed
  with React 18.3.1 and 19.3.0. The Button-only bundle is 20,144 bytes gzip within
  its 25kB budget, with the QR encoder and other heavy features excluded. The
  documentation download archive was refreshed.

Local evidence is in ignored `.preview/qr-code-qa/production.json`, screenshots,
standalone SVGs, `.preview/qr-code-*.log`, and `apps/docs/test-results/`. Decoding
uses rasterized SVG pixels; physical camera scanning, printed output, other
browser engines, physical mobile devices and screen-reader sessions were not
tested. Custom colors and small sizes need application-specific scanning checks.
