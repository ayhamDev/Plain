# Dropzone file selection

Integrated after `4cfcc43`, with a pending minor Changeset for `@plain/ui`.
The manifest remains the local 0.2.0 candidate; no npm publication is implied.

`Dropzone`, `DropzoneProps` and `DropzoneRenderState` are exported through the
core and existing advanced entry points. The full drop area is a native file
input: labels, refs, names, associated forms, required/disabled state, picker
events and keyboard browsing belong to that control. File-only drag feedback,
custom presentational content, removable selected files, rejection feedback and
live selection status are included. File selection stays local; applications own
uploading and server validation.

FileUpload and Dropzone share accept/size/count validation and native FileList
assignment. A selection replaces the previous batch; any invalid file rejects the
whole batch while retaining the previous accepted files. Controlled proposals
remain pending until their parent commits them. Twelve typed theme aliases and
fifteen styling slots support local customization, with neutral defaults,
English/Arabic messages, RTL, reduced motion and unstyled composition.

Native browser tests found that reset listeners' microtasks could restore files
before the browser's default reset action cleared them. Both upload components
now restore FileList after that action from committed React state, with timer
cleanup. Other controls keep their existing reset behavior. The new documentation
page includes a working example, property controls, copyable source and API notes.
