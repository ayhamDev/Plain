# P.UI 0.3.0

**Status:** Validated local release; not published to a registry.
**Package:** `@plain/ui`. **Date:** November 22, 2026.
**Source candidate:** `8d02e77802badacf3526093688baab262cfedfcf`, based on
`c479dbbee28a0248c6fb834291c01f5a03f6dc28`. Validation covers the code and
archive in that commit; this record adds its final revision and release status.

## Consumer changes

This is the third release, **0.3.0**, following 0.2.0. It includes the accumulated
component improvements and the production import/runtime audit. The package and
docs app retain their workspace ownership; the private root is not installable.

- Focused implementation modules, direct component/chart imports and optional CSS
  groups. Root and grouped exports retain the same component identities.
- Virtualized PhoneInput country choices with full-data search, measured rows,
  localized labels, keyboard navigation, selected-country scrolling and an active
  descendant that remains mounted. Full phone-number metadata is retained.
- Select sheet presentation uses the original Sheet/Vaul engine for entry/exit,
  handle dragging, overlay dismissal and focus. The Sheet adapter loads on first
  sheet use. Adaptive activation opens on release so a cold-loaded panel does not
  carry a stale opening pointer into the first option interaction.
- Dialog entry/exit defaults match the documented 320ms/200ms timing and retain
  component timing overrides and reduced-motion behavior. Documentation prose
  wraps long API names without extending mobile RTL pages.
- Shared responsive query subscriptions, fixed-layout subscription avoidance and
  stable unchanged styling contexts. Chart wrappers retain their own engines;
  time-only controls avoid the month-calendar renderer.
- PhoneInput, Item, List, Dropzone, QRCode; detached DataTable controls; independent
  table toolbar/selection modes; segmented progress, composable card/empty states,
  tab variants, shared field appearances, textarea resizing and tooltip props.
- Provider localization, scoped RTL/tokens, mobile picker sheets and date/time
  steps, month/year choices, persistent range review, stable time wheels and
  12/24-hour configuration. Full-viewport panels, safe drag gestures, layout
  presence and restrained optional scrolling effects share motion policy.
- Theme-coordinated color utilities, tonal chart colors, activity heatmaps,
  refined Gantt timelines and shape-aware chart skeletons. QRCode retains the final
  draw reveal and circular dot-field customization.

The [package changelog](../../packages/ui/CHANGELOG.md) describes final behavior,
rather than listing superseded intermediate implementations. The current site has
an upgrade guide, updated installation/performance guidance and API examples.
0.2.0 documentation is frozen at the base revision above; 0.1.0 stays pinned at
`0188733`. Archives retain their own implementations, assets and downloads.

## Migration

No supported 0.2 import or component prop is removed by the optimization. Existing
root/grouped imports and the complete `styles.css` continue to work. Direct
imports reduce the module graph and provide explicit boundaries:

```tsx
import { PlainProvider } from '@plain/ui/provider';
import { Input } from '@plain/ui/input';
import { PhoneInput } from '@plain/ui/phone-input';
import { TimePicker } from '@plain/ui/time-picker';
import { BarChart } from '@plain/ui/bar-chart';
```

Select, Combobox and MultiSelect keep `presentation="popover"` defaults. Choose
`"auto"` for mobile adaptation or `"sheet"` to force it. PhoneInput keeps its
`"auto"` default. Configure visible/localized sheet titles when appropriate.
Phone-country rows are virtualized: code should use the public country/value
props rather than count or query all options in the DOM. Internal cmdk markup in
that country list is replaced by the virtual combobox/listbox.

For CSS, keep the complete stylesheet or choose `core.css` plus feature files.
Do not import both foundations. See the [CSS recipes and exact measurements](../performance/README.md).
Use public styling slots/tokens rather than implementation class strings. Preserve
the documented Material engine pin; this release does not upgrade domain engines.

The historical 0.1 migration still requires renaming `@plainui/react` imports to
`@plain/ui`. Consumers should review the cumulative interaction/default changes in
the changelog when upgrading from an early 0.2 integration snapshot.

## Production measurements

The audit compares production-minified ESM consumers with the pinned 0.2 package,
using its own compiled dependencies. React/ReactDOM are external, engine code is
included, and CSS is measured separately. Isolated component sizes are not additive.

- Input: approximately 64.9 → 13.4 KiB eager gzip (79% reduction).
- NumberInput: 95.1 → 22.0 KiB (77% reduction).
- Dialog: 77.7 → 34.7 KiB (55% reduction).
- Core CSS: approximately 21.6 KiB gzip versus 32.6 KiB for the complete stylesheet.
- The gate verifies 126 runtime entries, 29 direct-versus-root/grouped bundle
  pairs and 11 CSS exports. It exposes deferred and independently compressed
  transfer sizes and rejects unrelated engine retention in selected probes.

See [the machine-readable report](../performance/0.3.0-bundles.json) for all cases,
budgets, methodology and deferred costs. Dependency installation size and
sourcemaps are separate from browser transfer size.

and time-budget contention. Functional defects found during the refactor,
including skeleton inference, the initial sheet option click, dialog timing and
mobile prose overflow, were fixed and rechecked. The owned preview was restarted
after changing the version registry so archive requests used the new registry.

Browser checks used installed Chrome **157.0.8103.79** with 320px, 390px and
desktop layouts, light/dark and LTR/RTL appearances, touch emulation and
reduced/normal motion. The country-list probe kept fewer than 40 options mounted
while reaching the selected country, either end of the data set and wheel-scrolled

Automated accessibility checks do not establish complete conformance. Application
software keyboards, assistive technologies and physical low-end device timing
remain separate integration checks.

Run the scoped browser assertions with the default development server:

